# 00. 概要 — 目的・設計判断・要確認事項

## 目的

ユーザー（Notta BtoB営業推進担当・非エンジニア）のPC作業を定期スクリーンショットで記録し、Claude APIで解析して以下を**自動構築・自動更新**する。

1. **操作マニュアル** — ステップごとのスクリーンショット付き手順書。同一作業の再実行で更新される
2. **ナレッジノート** — 作業中の気づき・学びの蓄積
3. **日次作業ログ** — 「今日何をしたか」のMarkdown（日報の種）

生成物はローカルの `~/ScreenKnowledge/vault/` にMarkdownで保存され、ローカル検索UI（Phase 4）でいつでも取り出せる。

## 用語

| 用語 | 意味 |
|---|---|
| tick | キャプチャデーモンの1回の撮影試行（既定30秒間隔＋ウィンドウ切替時） |
| frame | 1 tickの記録。**メタデータ行は毎tick必ず記録**し、画像は重複除去を通過した場合のみ保存 |
| session | アプリ連続性と時間ギャップでグルーピングされた作業単位（例:「HubSpotで商談更新 14:02-14:31」） |
| mark | ユーザーが「今の作業をマニュアル化」と宣言した区間。高頻度キャプチャ＋即時解析＋確実にマニュアル化 |
| keyframe | セッションからサンプリングされた代表画像（API解析に送る、セッションあたり最大12枚） |
| vault | 生成物の保存先 `~/ScreenKnowledge/vault/`（manuals / knowledge / daily） |

## 確定済み設計判断（変更する場合は関連docsをすべて更新すること）

1. **毎tickメタデータ行を記録、画像のみpHashで間引く。** 重複除去は「画像を保存するか」だけを決め、タイムラインには穴を作らない。ウィンドウ切替時・5分毎キーフレーム・マーク中は必ず保存
2. **Batch APIは夜間バッチ専用。** Batchは「ほとんど1時間以内・最大24時間」のため毎時処理には不適。未マークセッション=夜間Batch（50%割引）、マーク済みセッション=クローズ時に通常APIで即時解析。デーモン起動時にキャッチアップ（夜間スリープ対策）、提出後6時間未完了なら通常APIへフォールバック
3. **structured outputs（`messages.parse` + Pydantic）でJSONパース失敗系を排除。** Batch経由でも `output_config.format` を使い、収集時に同じPydanticモデルで検証
4. **トレイは pystray(Windows) / rumps(macOS) の2バックエンド。** メインスレッド=トレイ、キャプチャ・解析・削除ジョブ=ワーカースレッド。マーク操作の主経路はトレイメニュー（追加権限不要）。グローバルホットキーはWindowsのみ既定ON、macOSは既定OFF（アクセシビリティ権限の摩擦回避、Phase 3で任意対応）
5. **SQLiteは単一ライター規律。** デーモンプロセスが全書き込みを集約（WAL + busy_timeout=5000ms）、ビューアはread-only接続。詳細は docs/02
6. **FTS5は trigram トークナイザ。** 既定のunicode61は日本語を分割できず検索が機能しない。`sk doctor` で利用可否を検査し、不可ならLIKE検索へ縮退
7. **macOS画面収録権限の「無音失敗」対策を必須化。** 権限なしでもエラーにならず壁紙のみ写り、ウィンドウタイトルも空になる。preflight＋自己診断を `sk doctor` とデーモン起動時に実施。Windowsは起動時にPer-Monitor-V2 DPI awarenessを設定し、アクティブウィンドウのあるモニタのみ撮影
8. **コストは多層防御。** pHash重複除去 → キーフレーム抽出（≤12枚/セッション）→ 送信前1024pxダウンスケール → 夜間Batch50%割引 → 日次保存枚数上限 → 月次予算ハードストップ（超過時もキャプチャ継続・解析のみ滞留）。全API usageをSQLiteに記録
9. **ブラウザはタブ単位でセッション分割しない。** ウィンドウタイトル列（タブ名を含む）をLLMに渡して作業内容を判断させる。60秒以内の一時的なアプリ切替はセッションを分断しない
10. **マニュアルは更新が原則。** 新セッションは既存マニュアルカタログとマッチング（Haiku）し、一致すればリビジョン更新（旧版は `.history/` へ退避）。低確信時は新規ドラフト側に倒す（既存マニュアルを壊さない）。全生成物に「自動生成 — 内容を確認してから共有してください」フッター必須

## モデル・費用の方針

| 用途 | 設定キー | 既定値 | 単価（USD/1Mトークン・2026-07時点） |
|---|---|---|---|
| セッション解析（画像入力） | `api.analysis_model` | `claude-haiku-4-5` | in $1.0 / out $5.0 |
| マニュアル・日次ログ合成 | `api.synthesis_model` | `claude-sonnet-5` | in $3.0 / out $15.0（〜2026-08-31は導入価格 $2.0/$10.0） |

- 画像トークンは約 `(幅×高さ)÷750`。1024px長辺で約800トークン/枚
- 想定コスト: 1日約1,300tick → 15〜40セッション → 解析画像≤480枚/日 ≈ 入力0.45Mトークン → **月$10〜25程度**（夜間Batchでさらに半減）。既定予算 `budget.monthly_usd: 25`
- 品質を上げたい場合は `synthesis_model` を `claude-opus-4-8`（$5/$25）に変更可能
- **実装セッション開始時に必ず最新のモデルID・価格を確認**（`claude-api` スキル or Models API）し、`config.example.yaml` と本表を更新すること

# BusinessAgent

NottaのBtoB営業を推進するための、役割別AIエージェント環境です。Claude Codeのカスタムサブエージェント機能を使い、経営・営業・法務・技術の各役割のエージェントと協働できます。

## エージェント一覧

| エージェント | 役割 | 主な相談内容 | モデル |
|---|---|---|---|
| `marketing-director` | マーケティングダイレクター | リード獲得施策、ABM、コンテンツ企画、競合ポジショニング | sonnet |
| `sales-director` | 営業責任者 | 営業戦略、商談戦略、提案書・見積もりレビュー、個別商談の値引き判断 | inherit |
| `coo` | COO | 事業計画、部門間の優先順位調整、価格戦略・値引きポリシー、KPI設計 | inherit |
| `legal` | 法務 | 契約レビュー（NDA・利用契約）、個人情報保護、広告表現チェック | inherit |
| `cto` | CTO | セキュリティチェックシート対応、技術的なRFP回答、連携・SSO等の技術要件 | inherit |

エージェント定義は [`.claude/agents/`](.claude/agents/) にあります。判断の重い役割はセッションのモデルを継承（inherit）し、定型度の高い役割はsonnet指定でコストと速度を優先しています。

### 役割の境界

重複しやすい領域は次のように振り分けています。

- **値引き・価格**: 個別商談の判断は `sales-director`、ポリシー・プラン体系の設計は `coo`
- **セキュリティチェックシート**: 技術仕様の設問は `cto`、契約・法令の設問は `legal`

## 使い方

このリポジトリでClaude Codeを起動し、普通に日本語で依頼するだけです。内容に応じて適切なエージェントが自動的に起動します。

```
このNDAのドラフトをレビューして          → legal が対応
A社向けの提案書の構成を考えて            → sales-director が対応
来期のリード獲得施策を3つ提案して        → marketing-director が対応
```

特定のエージェントを名指しすることもできます。

```
cto として、このセキュリティチェックシートの回答案を作って
coo の視点で、この値引き要求を受けるべきか判断して
```

複数の役割の意見が欲しい場合は、並行して聞くこともできます。

```
この代理店契約の件、legal と coo それぞれの意見をまとめて
```

## 営業成績レポート（HubSpot連携）

HubSpotのデータから四半期・月次の営業成績レポートを作成できます。手順と集計定義（新規MRR絞り込み、納品日3フィールド横断・重複控除など）は [`.claude/skills/sales-report/`](.claude/skills/sales-report/) にスキルとして定義されています。レポートは `reports/` 配下にMarkdownで保存されます。

利用にはHubSpotへの接続が必要です。いずれかを設定してください。

1. **HubSpot MCPコネクタ**（推奨）: claude.ai の「設定 > コネクタ」でHubSpot公式コネクタを接続
2. **プライベートアプリトークン**: Claude Codeの環境設定で環境変数 `HUBSPOT_ACCESS_TOKEN` を登録（HubSpotの「設定 > 連携 > プライベートアプリ」で発行。Deals・Ownersの読み取りスコープが必要）

```
Q3の営業成績をHubSpotのデータから報告して   → sales-report スキルがレポートを生成
```

レポートには実際の顧客・金額データが含まれるため、リモートへpushする前に内容を確認してください。

## エージェントのカスタマイズ

各エージェントの知識や行動原則は `.claude/agents/` 配下のMarkdownファイルを編集することで調整できます。実際の商談や社内ルールに合わせて、以下のような情報を追記していくと精度が上がります。

- 最新の料金プラン・機能リスト
- 実際の競合比較資料・勝ちパターン
- 社内の値引きポリシー・契約ひな形の方針
- セキュリティチェックシートの過去回答集

## 注意事項

- `legal` の出力は正式な法律意見ではありません。重要な契約は必ず弁護士・正式な法務プロセスで確認してください。
- `cto` は製品仕様を創作しないよう設計していますが、顧客提出前に必ず実際の仕様を確認してください。
